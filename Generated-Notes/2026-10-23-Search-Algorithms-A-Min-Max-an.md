# Search Algorithms: A*, Min-Max, and Heuristic Search

---

## 1. 🧱 The Core Concept

Heuristic search balances uninformed graph traversal with domain-specific knowledge to bypass the curse of dimensionality. Rather than exhaustively expanding state spaces ($O(b^d)$), we prune unpromising subtrees and direct exploration toward the goal.

```
                  [State Space Tree]
                         (S)
                       /     \
             h(n₁) << h(n₂)   h(n₂) large
                    /             \
                  (A)             [Pruned]
                 /   \
               (B)   (C) -> Goal (Admissible h(n) guarantees optimality)
```

### A* Search: Guided Shortest Path
A* evaluates nodes via the evaluation function:

$$f(n) = g(n) + h(n)$$

*   $g(n)$: Exact cost accumulated from the start node to $n$.
*   $h(n)$: Estimated cost from $n$ to the goal.

#### Admissibility vs. Consistency
*   **Admissibility**: An admissible heuristic never overestimates the true cost to reach the goal:
    
    $$\forall n, \quad 0 \le h(n) \le h^*(n)$$
    
    *Guarantee*: Tree-search A* is guaranteed to find an optimal path.
*   **Consistency (Monotonicity)**: A heuristic is consistent if, for every node $n$ and every successor $n'$ generated by an action with cost $c(n, a, n')$:
    
    $$h(n) \le c(n, a, n') + h(n')$$
    
    *Guarantee*: Graph-search A* is guaranteed to be optimal **without reopening closed nodes**. It satisfies the triangle inequality. Every consistent heuristic is admissible; the converse is not true.

```
       n  --- c(n, a, n') --->  n'
        \                       /
         \                     /
       h(n)                 h(n')
           \               /
            v             v
                 [ Goal ]
    Invariance: h(n) <= c(n, a, n') + h(n')
```

### Min-Max Search: Zero-Sum Game Theory
Min-Max formalizes optimal decision-making in adversarial, deterministic, perfect-information zero-sum games. Two agents compete: **Max** seeks to maximize the terminal payoff, while **Min** seeks to minimize it:

$$V(s) = 
\begin{cases} 
\text{Utility}(s) & \text{if } \text{Terminal}(s) \\
\max_{a \in \text{Actions}(s)} V(\text{Result}(s, a)) & \text{if } \text{Player}(s) = \text{Max} \\
\min_{a \in \text{Actions}(s)} V(\text{Result}(s, a)) & \text{if } \text{Player}(s) = \text{Min} 
\end{cases}$$

#### Alpha-Beta Pruning
Prunes branches that cannot influence the final decision.
*   $\alpha$: The minimum score that the maximizing player is assured of.
*   $\beta$: The maximum score that the minimizing player is assured of.
*   **Pruning Condition**: Terminate branch exploration when $\beta \le \alpha$.

| Parameter | Dijkstra | A* (Consistent) | IDA* | Min-Max (Alpha-Beta) |
| :--- | :--- | :--- | :--- | :--- |

| **Primary Bottleneck**| CPU time on dense graphs | Exhaustion of heap memory | Redundant state re-expansion | Branching factor explosion |

## 2. ⚙️ Under the Hood

### Deep Dive 1: A* Invariants, Memory Limits, and Graph Search

#### Inconsistent Heuristics and the Closed Set Dilemma
If $h(n)$ is admissible but **inconsistent**, the first path found to a node $n$ is not guaranteed to be optimal. 

```
          (Start)
          /     \
       g=1/       \g=10
        v         v
       (A)       (B)
        \         /
       g=5\     /g=1
          v   v
          (Goal)

If h(A) drastically underestimates relative to h(B), 
A* enters (Goal) via (A) with g=6 before evaluating (B) 
unless CLOSED nodes can be reopened.
```

To maintain optimality when $h(n)$ is inconsistent:
1. When finding a path to an already closed node with a lower $g(n)$, you must **reopen** it (remove it from `CLOSED`, place it back into `OPEN`).
2. This degenerates graph search worst-case runtime to $O(2^{|V|})$, making consistency non-negotiable for large graphs.

#### The ALT Algorithm (A*, Landmarks, Triangle Inequality)
In production routing engines (e.g., mapping road networks), dynamic point-to-point heuristics are generated via **Landmarks**:
1. Select a small set of landmark nodes $L \subset V$.
2. Precompute all-pairs shortest paths from/to all $l \in L$ using Dijkstra: $d(u, l)$ and $d(l, u)$.
3. Using the triangle inequality, formulate a consistent heuristic for any target $t$:

$$h(n) = \max_{l \in L} |d(n, l) - d(t, l)|$$

```
Landmark (L)
   / \
  /   \  d(n, L) - d(t, L) <= d(n, t)
 d(n,L) d(t,L)
 /       \
(n)----->(t)
   d(n,t)
```

#### Production-Grade A* Implementation (C++20 Style Mechanics)

Key production considerations:
* Avoid pointer-heavy node graphs (poor cache locality).
* Use a single **flat state array** or **compact hash map** to track $g$-costs and search status (UNVISITED, OPEN, CLOSED).
* The priority queue holds a lightweight `(f_score, node_id)` pair. If an entry's $g$-score in the state array is strictly less than the popped cost, skip it (lazy deletion).

```cpp
#include <vector>
#include <queue>
#include <limits>
#include <concepts>
#include <span>

struct Edge {
    uint32_t target;
    uint32_t weight;
};

struct NodeCost {
    uint32_t id;
    uint32_t f_score;
    bool operator>(const NodeCost& other) const { return f_score > other.f_score; }
};

template <typename HeuristicFunc>
requires std::is_invocable_r_v<uint32_t, HeuristicFunc, uint32_t, uint32_t>
std::vector<uint32_t> run_astar(
    uint32_t node_count,
    uint32_t start,
    uint32_t target,
    std::span<const std::vector<Edge>> adj_list,
    HeuristicFunc&& h) 
{
    constexpr uint32_t INF = std::numeric_limits<uint32_t>::max();
    std::vector<uint32_t> g_score(node_count, INF);
    std::vector<uint32_t> parent(node_count, INF);
    std::vector<uint8_t> closed(node_count, 0);

    // Min-heap storing {node_id, f_score}
    std::priority_queue<NodeCost, std::vector<NodeCost>, std::greater<NodeCost>> open_set;

    g_score[start] = 0;
    open_set.push({start, h(start, target)});

    while (!open_set.empty()) {
        auto [curr, curr_f] = open_set.top();
        open_set.pop();

        if (curr == target) {
            // Path reconstruction
            std::vector<uint32_t> path;
            for (uint32_t at = target; at != INF; at = parent[at]) path.push_back(at);
            std::reverse(path.begin(), path.end());
            return path;
        }

        if (closed[curr]) continue;
        closed[curr] = 1;

        for (const auto& edge : adj_list[curr]) {
            if (closed[edge.target]) continue;

            uint32_t tentative_g = g_score[curr] + edge.weight;
            if (tentative_g < g_score[edge.target]) {
                parent[edge.target] = curr;
                g_score[edge.target] = tentative_g;
                // Consistent h(n) means monotonic f along paths:
                // f(n') = g(n') + h(n')
                uint32_t f = tentative_g + h(edge.target, target);
                open_set.push({edge.target, f});
            }
        }
    }
    return {}; // No path found
}
```

### Deep Dive 2: Min-Max, Alpha-Beta Mechanics, and Move Ordering

#### The Mechanics of $\alpha$-$\beta$ Cutoffs

```
                  [MAX Node] (alpha=-inf, beta=+inf)
                 /          \
               (v=4)         \
              /               \
       [MIN Node]              [MIN Node] (alpha=4, beta=+inf)
        /     \                 /
     (Leaf)  (Leaf)          (Leaf) 
       4       7               2  <-- Beta-cutoff! (beta <= alpha -> 2 <= 4)
                                  Remaining children of this MIN node are SKIPPED.
```

Alpha-Beta pruning's efficiency depends entirely on **move ordering**:
* **Worst-case ordering** (worst moves examined first): Alpha-Beta evaluates all leaf nodes. Complexity remains $O(b^d)$.
* **Optimal ordering** (best moves evaluated first): Complexity drops to:

$$O(b^{d/2})$$

This effectively **doubles the search depth** for the same compute budget.

```
Theoretical Limits:
Branching factor b = 30, Depth d = 10
Plain Min-Max: 30^10 ≈ 5.9 × 10^14 evaluations
Optimal Alpha-Beta: 30^5 ≈ 2.43 × 10^7 evaluations (Achievable via move ordering)
```

#### Transposition Tables & Zobrist Hashing
Redundant paths to the same game state waste search budget.

```
       Move Sequence A: 1. e4 e5 2. Nf3 Nc6
       Move Sequence B: 1. Nf3 Nc6 2. e4 e5
       ==> Identical board configuration reached via different permutations.
```

1. **Zobrist Hashing**:
   * Pre-generate a table of pseudo-random 64-bit integers: `Table[Piece][Square]`.
   * Compute initial hash: $H = \bigoplus_{i} \text{Table}[\text{Piece}_i][\text{Square}_i]$.
   * Incrementally update state with a single XOR operations: $H' = H \oplus \text{Table}[\text{Piece}][\text{From}] \oplus \text{Table}[\text{Piece}][\text{To}]$.
2. **Transposition Table Cache Line Structure**:
   * Hash Key (64-bit).
   * Search Depth (8-bit).
   * Node Type (2-bit: `EXACT`, `LOWERBOUND` [failed high, $\beta$-cutoff], `UPPERBOUND` [failed low, all children $<\alpha$]).
   * Best Move (16-bit).
   * Evaluation Value (16-bit).

```cpp
enum class NodeFlag : uint8_t { EXACT, LOWERBOUND, UPPERBOUND };

struct TTEntry {
    uint64_t zobrist_key; // Verify against hash collisions
    int16_t  score;
    uint8_t  depth;
    NodeFlag flag;
    uint16_t best_move;
};
```

#### Pathologies & Advanced Mitigations
*   **The Horizon Effect**: A catastrophic loss is inevitable, but the engine delays it past the maximum search depth by playing stalling moves (e.g., sacrificing intermediate pieces).
    *   *Solution*: **Quiescence Search**. At depth 0, do not evaluate immediately. Continue searching "noisy" moves (captures, promotions, tactical checks) until the board reaches a "quiet" state.
*   **Move Ordering Pipeline**:
    1. Principal Variation (PV) move from the Transposition Table.
    2. Winning/equal tactical captures (via MVV-LVA: *Most Valuable Victim - Least Valuable Attacker*).
    3. Killer Moves (moves that caused a $\beta$-cutoff in a sibling node at the same depth).
    4. History Heuristic (moves that frequently cause cutoffs across the whole tree).
    5. Non-tactical quiet moves.

## 3. ⚠️ The Interview Warzone

### Scenario 1: Ultra-Low-Latency Ride-Hailing Routing Engine

#### The Problem
You are building the routing engine for a global ride-hailing company. You must process 50,000 shortest-path queries/sec over a graph representing North America ($|V| \approx 30 \times 10^6$, $|E| \approx 70 \times 10^6$). Graph edge weights reflect real-time live traffic, which updates every 60 seconds. Median response time must be $<5\text{ ms}$.

#### Follow-Up Questions

```
                                  [Graph Size: 30M Nodes]
                                             |
                   +-------------------------+-------------------------+
                   |                                                   |
           [Dijkstra / A*]                                   [Preprocessing Trade-offs]
        O(|E| + |V|log|V|)                                             |
   Latency: ~500ms - 2s per query                     +----------------+----------------+
   Verdict: FAILS SLA (Req: <5ms)                     |                                 |
                                             Contraction Hierarchies           Customizable Contraction
                                             (Static Weights: FAST)            Hierarchies (Dynamic: FAST)
                                             Preprocessing: 30-60 mins         Customization: 2-3 seconds
```

*Interviewer:* "Plain A* with Euclidean distance heuristic takes roughly 250ms–1.5s on continental queries due to exploring tens of thousands of vertices in the priority queue. How do you hit $<5\text{ ms}$?"

*Candidate Strategy:* "Point-to-point continental search requires preprocessing techniques. Standard A* or Bidirectional A* even with ALT won't reliably hit 5ms at 50k QPS without thousands of machines. We must decouple the graph topology from the metric."

*Interviewer:* "If you use **Contraction Hierarchies (CH)**, edge contraction takes 45 minutes of precomputation. How do you reconcile CH with real-time traffic updates every 60 seconds?"

#### The Response

1. **Architecture: Customizable Contraction Hierarchies (CCH) / Customizable Route Planning (CRP)**
   * Split routing into a 3-stage pipeline:
     * **Phase 1: Metric-Independent Preprocessing (Topology only)**: Contract nodes using a nested dissection ordering (separator trees). This runs *once* when road infrastructure changes (months).
     * **Phase 2: Customization (Metric updates)**: When edge weights (traffic) change every 60 seconds, recompute the shortcut weights over the fixed contraction hierarchy. Because the structure is fixed, this takes **1-3 seconds across 30M nodes** using multi-threaded bottom-up evaluation on the tree decomposition.
     * **Phase 3: Query Phase**: Bidirectional search over the contracted graph. It visits only upwards edges in the hierarchy:
       
       $$\text{Vertices Visited} \le 2 \times \text{Tree-Depth} \approx 2 \times O(\log |V|) \approx 1,000 \text{ to } 2,000 \text{ nodes}$$
       
       Query latency drops to **$\approx 0.5 - 2\text{ ms}$**.

2. **Heuristic Selection in CCH Search**:
   * Upward-search avoids exploring off-direction nodes. The search traverses:
     
     $$\text{Forward: } s \to \text{LCA}, \quad \text{Backward: } t \to \text{LCA}$$
     
     Where $\text{LCA}$ is the lowest common ancestor in the contraction tree.

3. **Memory Footprint**:
   * Store the contracted shortcuts in a Flat Array using Forward-Star (CSR: Compressed Sparse Row) representation to ensure zero pointer indirection and full L1/L2 cache-line utilization during upward traversal.

### Scenario 2: Chess Engine Under a Hard 100ms Per-Move Deadline

#### The Problem
Design the search framework for an AI board engine (branching factor $b \approx 35$). The system must execute its move within an exact budget of 100ms. If the execution crosses 100ms, your engine forfeits. 

#### Follow-Up Questions

*Interviewer:* "If you run an Alpha-Beta search set to a fixed depth $d=8$, and it takes 30ms, you leave compute on the table. If you set $d=9$, it might explode to 800ms due to the dynamic branching factor, and you forfeit. How do you solve this deterministically?"

*Candidate Strategy:* "You cannot use a fixed-depth search in game engines with non-uniform branching factors. You must use **Iterative Deepening Depth-First Search (IDDFS)** combined with a **Time-Check Interrupt Monitor** and **Aspiration Windows**."

*Interviewer:* "Doesn't Iterative Deepening waste immense compute re-searching depths $1, 2, \dots, d-1$?"

#### The Response

1. **The Asymptotic Redundancy Proof**:
   * The overhead of re-searching previous depths is mathematically negligible for $b \gg 1$:

$$\frac{\sum_{i=1}^d b^i}{b^d} = \frac{b}{b - 1} \approx \frac{35}{34} \approx 1.029$$

   * **The re-search overhead is under 3%**, while providing critical benefits:
     * The Transposition Table retains the Principal Variation (PV) of depth $d-1$.
     * Depth $d$ searches the prior best move **first**, yielding near-optimal move ordering and driving Alpha-Beta towards its theoretical limit ($O(b^{d/2})$).

2. **Time Management & Safe Interruption**:
   * Run Iterative Deepening: Depth 1, 2, 3...
   * Check an atomic timer flag every 2048 node evaluations (using bitmask `if ((nodes_evaluated & 2047) == 0)` to minimize syscall overhead):
     * If elapsed time $> 60\%$ of total budget (60ms), **do not start iteration $d+1$**.
     * Return the completed PV move from iteration $d$.
   * If a timeout occurs *mid-iteration*, immediately abort via an exception or unwind flag, discard the partially searched depth $d$, and fall back to the move from depth $d-1$.

3. **Aspiration Windows**:
   * Instead of searching depth $d$ with wide bounds $(\alpha = -\infty, \beta = +\infty)$, initialize:
     
     $$\alpha = \text{Score}_{d-1} - \delta, \quad \beta = \text{Score}_{d-1} + \delta$$
     
     Where $\delta \approx 0.25$ of a pawn value.
   * If the search stays within bounds, pruning increases significantly. If it fails low ($< \alpha$) or high ($> \beta$), widen the window and re-search.

### Scenario 3: Real-Time Multi-Agent Pathfinding (MAPF) in Automated Warehouses

#### The Problem
You are the tech lead for an automated fulfillment center with 2,000 mobile robots moving on an 8-connected grid. Each robot is assigned arbitrary picking targets. Robots cannot collide into the same cell at the same time (Vertex Collision), nor can they traverse the same edge in opposite directions at the same time step (Edge Collision).

```
Vertex Collision:       Robot A (t=2) ----> [ Cell (x,y) ] <---- Robot B (t=2)
Edge Collision:         Robot A [x1, y1] === (t -> t+1) ===> [x2, y2]
                        Robot B [x2, y2] === (t -> t+1) ===> [x1, y1]
```

#### Follow-Up Questions

*Interviewer:* "Could we model this as a unified state-space A* problem where a state is the joint position of all 2,000 robots?"

*Candidate Strategy:* "No. If a single robot has $b=8$, 2,000 robots yield a combined branching factor of $b^{2000} \approx 8^{2000}$. The state space explodes instantly. You must use **Conflict-Based Search (CBS)** or **Decoupled Priority Planning**."

*Interviewer:* "Priority planning is incomplete and often leads to deadlocks. How does **Conflict-Based Search (CBS)** guarantee both **completeness** and **optimality**?"

#### The Response

1. **Two-Level Algorithm Architecture**:
   * CBS decomposes the problem into a two-level optimization:
     * **Low-Level**: Runs single-agent **Space-Time A\*** ($x, y, t$). It finds the shortest path for an individual agent while treating added constraints as dynamic obstacles.
     * **High-Level**: Explores a **Conflict Tree (CT)** using best-first search.

```
                         [Root: Unconstrained Paths]
                                      |
                     Found Conflict: A1 & A2 at (x,y) at t=4
                                     / \
                                    /   \
  Constraint: A1 cannot be at (x,y,4)   Constraint: A2 cannot be at (x,y,4)
                 |                                      |
       [Re-run Low-level A1]                  [Re-run Low-level A2]
```

2. **Conflict Tree (CT) Mechanics**:
   * Each node $C$ in the CT contains:
     * A set of constraints across all agents (e.g., `Agent 4 cannot occupy (12, 8) at t=14`).
     * A set of individual paths for all $K$ agents.
     * Cost: $\sum_{i=1}^K \text{cost}(\text{path}_i)$.
   * **Branching step**:
     * Detect the *first* collision between any two agents $A_i$ and $A_j$ at location $v$ and time $t$.
     * Create two child nodes:
       * **Child 1**: Add constraint $(A_i, v, t)$. Re-run low-level Space-Time A* *only* for $A_i$.
       * **Child 2**: Add constraint $(A_j, v, t)$. Re-run low-level Space-Time A* *only* for $A_j$.
   * **Optimality**: Since the high-level search traverses the Conflict Tree using Best-First Search on total path cost, the first conflict-free leaf node found is **globally optimal**.

3. **Handling High Agent Density**:
   * Standard CBS scales poorly when agent density causes thousands of conflicts. At warehouse scale, upgrade to **ECBS (Enhanced CBS)**:
     * Use focal search with sub-optimality bound: Cost $\le (1 + \epsilon) \cdot \text{Cost}^*$.
     * Replaces standard high-level best-first expansion with a heuristic that prioritizes resolving the conflict that frees up the most congested spatial bottleneck. This brings runtimes down from exponential to polynomial in practical distribution centers.
