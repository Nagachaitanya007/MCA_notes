# Search Algorithms: A*, Min-Max, and Heuristic Search

---

## 1. 🧱 The Core Concept

Search algorithms operate over **state spaces** formalized as directed graphs $G = (V, E)$, where vertices represent domain configurations and edges represent valid transitions. In FAANG-level systems, these spaces are rarely materialized in memory upfront; they are lazily expanded via successor functions under severe time and memory constraints.

```
                    ┌─────────────────────────┐
                    │  State Space Search     │
                    └────────────┬────────────┘
                                 │
         ┌───────────────────────┴───────────────────────┐
         ▼                                               ▼
┌─────────────────────────┐                     ┌─────────────────────────┐
│   Single-Agent Search   │                     │   Adversarial Search    │
│  (Pathfinding/Planning) │                     │   (Zero-Sum Two-Player) │
└────────────┬────────────┘                     └────────────┬────────────┘
             │                                               │
             ├─ Dijkstra: f(n) = g(n)                        ├─ Min-Max: Exh. Tree Search
             ├─ Greedy:   f(n) = h(n)                        ├─ α-β Pruning: Branch & Bound
             └─ A*:       f(n) = g(n) + h(n)                 └─ Enhancements: TT, Negamax
```

### Heuristic Single-Agent Search (A*)
A\* bridges uniform-cost search (Dijkstra) and greedy best-first search using an evaluation function:

$$f(n) = g(n) + h(n)$$

*   $g(n)$: Exact path cost from the start state $s_0$ to state $n$.
*   $h(n)$: Heuristic estimate of the minimal path cost from $n$ to a target goal state $t \in T$.
*   $f(n)$: Estimated total cost of the cheapest solution passing through $n$.

By balancing backward path accumulation with forward heuristic projection, A\* minimizes node expansions while preserving path optimality under specific heuristic constraints.

### Adversarial Search (Min-Max)
Min-Max governs discrete, zero-sum, perfect-information two-player games (Player $\text{MAX}$ vs. Player $\text{MIN}$). The state space is modeled as an alternating game tree evaluated recursively from terminal payoffs:

$$V(s) = 
\begin{cases} 
\text{Utility}(s) & \text{if } \text{Terminal}(s) \\
\max_{a \in \text{Actions}(s)} V(\text{Result}(s, a)) & \text{if } \text{Player}(s) = \text{MAX} \\
\min_{a \in \text{Actions}(s)} V(\text{Result}(s, a)) & \text{if } \text{Player}(s) = \text{MIN}
\end{cases}$$

Because real-world game trees are intractable ($b^d \approx 35^{80}$ for Chess), minimax truncates search at a fixed depth $d$ using a static evaluation function $e(s)$, augmented with branch-and-bound pruning ($\alpha$-$\beta$).

## 2. ⚙️ Under the Hood

### A\* Mechanics: Invariants, Admissibility, and Consistency

A\* maintains two collections:
*   `OpenSet`: Priority Queue ordered by $f(n)$, storing discovered nodes awaiting expansion.
*   `ClosedSet`: Hash set of nodes already expanded, preventing infinite cycles.

```
         Start [g=0, h=7, f=7]
                 │
        ┌────────┴────────┐
   Node A [g=2]      Node B [g=4]
   h=6, f=8          h=2, f=6  <-- Lowest f(n), expanded first!
```

#### The Two Golden Conditions

1. **Admissibility**: A heuristic is admissible if it never overestimates the true cost to reach the nearest goal $h^*(n)$:
   $$\forall n, \quad 0 \le h(n) \le h^*(n)$$
   *Consequence*: Guarantees optimality in **Tree Search** (where states are not deduplicated across paths).

2. **Consistency (Monotonicity)**: A heuristic is consistent if, for every node $n$ and every successor $n'$ generated by action $a$ with step cost $c(n, a, n')$:
   $$h(n) \le c(n, a, n') + h(n')$$
   *(Form of the Triangle Inequality)*
   *Consequence*: Guarantees that $f(n)$ is monotonically non-decreasing along any path. Crucially, **the first time A\* selects a node from the `OpenSet` for expansion, its $g(n)$ is guaranteed to be optimal**. 
   *Architectural impact*: If $h(n)$ is consistent, you **never** need to re-open nodes in the `ClosedSet`. If $h(n)$ is merely admissible but *inconsistent*, an expanded node may need to be returned to the `OpenSet` if a cheaper path is found later, degrading time complexity from $O(|V| \log |V|)$ to $O(2^{|V|})$.

#### Production-Ready A\* Implementation (C++20 Style)

```cpp
#include <vector>
#include <queue>
#include <unordered_map>
#include <limits>
#include <concepts>

template <typename State>
concept SearchState = requires(State a, State b) {
    { a == b } -> std::convertible_to<bool>;
    { std::hash<State>{}(a) } -> std::convertible_to<std::size_t>;
};

template <SearchState State>
struct Node {
    State state;
    double g_cost;
    double f_cost;

    bool operator>(const Node& other) const {
        return f_cost > other.f_cost; // Min-heap
    }
};

template <SearchState State, typename CostFunc, typename HeuristicFunc, typename NeighborFunc>
std::vector<State> a_star_search(
    const State& start,
    const State& goal,
    NeighborFunc get_neighbors, // State -> vector<pair<State, double>>
    HeuristicFunc h             // State -> double
) {
    std::priority_queue<Node<State>, std::vector<Node<State>>, std::greater<Node<State>>> open_set;
    std::unordered_map<State, double> g_score;
    std::unordered_map<State, State> came_from;

    g_score[start] = 0.0;
    open_set.push({start, 0.0, h(start)});

    while (!open_set.empty()) {
        Node<State> current = open_set.top();
        open_set.pop();

        if (current.state == goal) {
            // Reconstruct path
            std::vector<State> path;
            State curr = goal;
            while (curr != start) {
                path.push_back(curr);
                curr = came_from[curr];
            }
            path.push_back(start);
            std::reverse(path.begin(), path.end());
            return path;
        }

        // Lazy deletion: skip if found a strictly better path to current.state already
        if (current.g_cost > g_score[current.state]) {
            continue;
        }

        for (const auto& [neighbor, edge_cost] : get_neighbors(current.state)) {
            double tentative_g = current.g_cost + edge_cost;
            auto it = g_score.find(neighbor);

            if (it == g_score.end() || tentative_g < it->second) {
                came_from[neighbor] = current.state;
                g_score[neighbor] = tentative_g;
                double f = tentative_g + h(neighbor);
                open_set.push({neighbor, tentative_g, f});
            }
        }
    }
    return {}; // No path found
}
```

### Min-Max & $\alpha$-$\beta$ Pruning Architecture

Min-Max exhaustively checks all paths to leaf nodes. With branching factor $b$ and search depth $d$, runtime is $\mathcal{O}(b^d)$, which is prohibitive for real-time computation.

#### $\alpha$-$\beta$ Invariant
*   $\alpha$: The minimum score that the maximizing player is assured of (highest value found so far along path for MAX). Defaults to $-\infty$.
*   $\beta$: The maximum score that the minimizing player is assured of (lowest value found so far along path for MIN). Defaults to $+\infty$.
*   **Pruning condition**: As soon as $\alpha \ge \beta$ within a node evaluation, the current branch can be abandoned (pruned). The opponent has a proven alternative that prevents this sub-tree from ever being reached.

```
             MAX [α=-∞, β=+∞]
             /              \
         MIN [α=-∞, β=3]     MIN (Skip remaining if α >= β)
         /      \
      Leaf=3   Leaf=5
     (β=3)    (Ignored: 5 > 3)
```

#### Negamax Formulation with Transposition Table and Alpha-Beta

Production engines avoid separate `min` and `max` code paths by leveraging the zero-sum symmetry: $\max(a, b) = -\min(-a, -b)$. This yields the **Negamax** variant.

```python
from enum import IntEnum
from typing import Optional, Tuple

class NodeType(IntEnum):
    EXACT = 0
    LOWERBOUND = 1  # Beta-cutoff (All-node)
    UPPERBOUND = 2  # Alpha-cutoff (Fail-low)

class TranspositionTableEntry:
    __slots__ = ['depth', 'value', 'node_type', 'best_move']
    def __init__(self, depth: int, value: float, node_type: NodeType, best_move: any):
        self.depth = depth
        self.value = value
        self.node_type = node_type
        self.best_move = best_move

class NegamaxEngine:
    def __init__(self):
        self.tt = {} # Zobrist Hash -> TranspositionTableEntry

    def search(self, state, depth: int, alpha: float, beta: float, color: int) -> Tuple[float, any]:
        """
        color: +1 for MAX, -1 for MIN
        """
        alpha_orig = alpha
        state_key = state.zobrist_hash()

        # 1. Transposition Table Lookup
        tt_entry: Optional[TranspositionTableEntry] = self.tt.get(state_key)
        if tt_entry and tt_entry.depth >= depth:
            if tt_entry.node_type == NodeType.EXACT:
                return tt_entry.value, tt_entry.best_move
            elif tt_entry.node_type == NodeType.LOWERBOUND:
                alpha = max(alpha, tt_entry.value)
            elif tt_entry.node_type == NodeType.UPPERBOUND:
                beta = min(beta, tt_entry.value)
            if alpha >= beta:
                return tt_entry.value, tt_entry.best_move

        # Base case: Terminal or Leaf Depth
        if depth == 0 or state.is_terminal():
            return color * self.quiescence_search(state, alpha, beta, color), None

        best_value = -float('inf')
        best_move = None
        
        # 2. Move Ordering (Essential: Explores TT best-move first)
        ordered_moves = self.order_moves(state, tt_entry.best_move if tt_entry else None)

        for move in ordered_moves:
            state.apply_move(move)
            # Negamax recursive step: negate window and score
            value, _ = self.search(state, depth - 1, -beta, -alpha, -color)
            value = -value
            state.undo_move(move)

            if value > best_value:
                best_value = value
                best_move = move
            
            alpha = max(alpha, value)
            if alpha >= beta:
                break  # Beta cutoff (Pruning)

        # 3. Transposition Table Store
        if best_value <= alpha_orig:
            flag = NodeType.UPPERBOUND
        elif best_value >= beta:
            flag = NodeType.LOWERBOUND
        else:
            flag = NodeType.EXACT
            
        self.tt[state_key] = TranspositionTableEntry(depth, best_value, flag, best_move)
        return best_value, best_move

    def quiescence_search(self, state, alpha: float, beta: float, color: int) -> float:
        """Mitigates the Horizon Effect by evaluating non-terminal 'noisy' tactical positions."""
        stand_pat = color * state.evaluate()
        if stand_pat >= beta:
            return beta
        if alpha < stand_pat:
            alpha = stand_pat

        for capture_move in state.get_noisy_moves(): # Captures/Checks only
            state.apply_move(capture_move)
            score = -self.quiescence_search(state, -beta, -alpha, -color)
            state.undo_move(capture_move)

            if score >= beta:
                return beta
            if score > alpha:
                alpha = score
        return alpha
```

#### Optimizations That Dictate Scale

1. **Move Ordering**: Alpha-Beta pruning complexity depends entirely on branching order:
   * **Worst-case** (ordered worst-to-best): Zero branches cut $\to \mathcal{O}(b^d)$.
   * **Best-case** (ordered best-to-worst): Node evaluations drop to $\mathcal{O}(b^{d/2})$. Effectively **doubles the search depth** for the same compute budget.
   * *Tools used*: Transposition Table move $\to$ Captures (MVV-LVA: Most Valuable Victim - Least Valuable Aggressor) $\to$ Killer Heuristic $\to$ History Heuristic.
2. **Horizon Effect Mitigation**: A fixed depth cut can evaluate a state right before a massive material loss (e.g., stopping 1 ply before a Queen is recaptured). **Quiescence Search** resolves this by extending the search beyond depth limit until only "quiet" (non-tactical) positions remain.

### Memory-Bounded Single-Agent Search: Dealing with $O(b^d)$ State Explosions

While Dijkstra/A\* are time-efficient, their spatial requirement is $\mathcal{O}(b^d)$ because the `ClosedSet` and `OpenSet` retain every state explored. If available RAM is exceeded, page thrashing halts throughput.

| Algorithm | Time Complexity (Worst) | Space Complexity | Optimality Guarantee | Completeness |
| :--- | :--- | :--- | :--- | :--- |
| **A\*** | $\mathcal{O}(b^d)$ | $\mathcal{O}(b^d)$ | Yes (if $h$ is admissible) | Yes |
| **IDA\* (Iterative Deepening A\*)** | $\mathcal{O}(b^d)$ (graph dependent) | $\mathcal{O}(d)$ | Yes (if $h$ is admissible) | Yes |
| **SMA\* (Simplified Memory-Bounded A\*)** | $\mathcal{O}(b^d)$ | $\mathcal{O}(\text{Memory Limit } M)$ | Yes (if $M \ge d$) | Yes |

*   **IDA\*** operates like iterative deepening DFS, but uses the $f(n)$ value to set cutoffs rather than raw depth. In each iteration, it performs a depth-first traversal, pruning any branch whose $f(n) > \text{threshold}$. The threshold for the next iteration becomes the minimum $f(n)$ value that exceeded the previous threshold. 
    *   *Trade-off*: Tiny memory footprint ($\mathcal{O}(d)$), but incurs heavy node re-expansion penalties in graphs with continuous edge weights.
*   **SMA\*** fills memory up to limit $M$. When full, it drops the worst node in the fringe (highest $f(n)$), backing up its value to the parent node so it can be re-generated if alternative paths fail.

## 3. ⚠️ The Interview Warzone

### Scenario 1: Ultra-Low Latency Routing Engine for Ride-Sharing
**Interviewer Prompt**: *"You are designing the routing engine for dynamic driver-rider pickup dispatch. The graph consists of continental-scale road networks (e.g., $50 \times 10^6$ intersections). Standard A\* takes 800ms—far too slow for our 20ms SLA. What do you do?"*

#### Probing Patterns & Red Herrings
*   *Interviewer pivot*: "Can we just precompute all-pairs shortest paths (Floyd-Warshall / APSP)?" (Trap: $\mathcal{O}(V^2)$ storage requires petabytes of RAM).
*   *Interviewer pivot*: "Can we scale this by running parallel worker threads running A\* on the same shared graph?" (Trap: Focuses on thread parallelism over algorithmic structure; priority queue synchronization becomes the bottleneck).

#### Staff-Level Response Architecture

```
                      Query: Start -> Target
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
   Hierarchical Graph (CH)              Bidirectional A*
   - Precompute upward shortcuts        - Forward from Start
   - Search space: ~O(log |V|)          - Backward from Target
   - Query time: < 2ms                  - Meet in middle via LandMarks (ALT)
```

1. **Algorithmic Transformation (Contraction Hierarchies - CH)**:
   *   Abandon plain A\* on flat topologies. Use **Contraction Hierarchies**.
   *   *Preprocessing Step*: Order nodes by importance (degree, shortcut count). Incrementally remove nodes and insert "shortcut edges" preserving shortest-path distance between remaining neighbors.
   *   *Query Step*: Bidirectional Dijkstra considering **only edges directed to higher-ranked nodes**. The forward search from the source and backward search from the target meet at the highest-rank node along the true path.
   *   *SLA Target*: Reduces search spaces from $50 \times 10^6$ nodes to $<2,000$ nodes; query execution latency drops from $800\text{ms} \to 1.5\text{ms}$.

2. **Heuristic Preprocessing (ALT: A\*, Landmarks, Triangle Inequality)**:
   *   Select a sparse set of $K$ fixed landmark vertices $L \subset V$. Precompute distances $d(L, v)$ and $d(v, L)$ for all $v \in V$.
   *   Apply Triangle Inequality for consistent lower-bounds:
       $$h(v) = \max_{l \in L} |d(l, v) - d(l, \text{Target})|$$
   *   Significantly tighter than Euclidean distance; avoids distortions introduced by winding roads, lakes, and one-way streets.

3. **Dynamic Topology Mutations (Real-time traffic updates)**:
   *   If edge costs shift dynamically, full CH re-contraction is too slow.
   *   *Architecture*: Apply **Customizable Contraction Hierarchies (CCH)**. Metric-independent hierarchy generation is computed upfront, while metric-dependent edge weights are mapped in parallel via GPU/SIMD kernels every 30–60 seconds without altering the underlying shortcut topology.

### Scenario 2: Serverless Game Engine with Strict Memory Limits
**Interviewer Prompt**: *"You are implementing a real-time Connect-Four/Chess service running on a constrained environment (AWS Lambda, 128MB RAM). The worker experiences unpredictable OOM errors during Min-Max searches when branch depth increases. How do you guarantee sub-100ms response times without hitting out-of-memory errors?"*

#### Probing Patterns
*   The interviewer wants to see if you manage allocations dynamically.
*   They are probing whether you know how to combine **Iterative Deepening**, **Transposition Table replacements**, and **Hard Time Slicing**.

#### Staff-Level Response Architecture

```
Time-Check Loop (Iterative Deepening Search):
Depth 1:  [Search completed: 2ms]   ──> Save Move
Depth 2:  [Search completed: 8ms]   ──> Save Move
Depth 3:  [Search completed: 32ms]  ──> Save Move
Depth 4:  [Timer expired at 98ms!]  ──> ABORT: Return Best Move from Depth 3
```

1. **Iterative Deepening Framework with Hard Cutoff**:
   *   Never invoke Min-Max to a deep fixed depth directly. Wrap the search in an **Iterative Deepening** loop: $d = 1, 2, 3, \dots$
   *   Poll an atomic hardware monotonic timer every $N$ ($N \approx 2048$) node evaluations. When `elapsed_time >= 90ms`, set an abort flag and unwind the call stack. 
   *   Always fall back to the complete move returned by the last fully traversed depth iteration ($d - 1$).

2. **Fixed-Size Ring-Buffer Transposition Table**:
   *   OOMs occur because naive hash tables grow unbounded ($\mathcal{O}(b^d)$).
   *   Enforce a **fixed-size bitmasked Transposition Table**. Allocate a single static array of $2^k$ entries (e.g., $2^{21}$ entries $\times 32\text{ bytes} \approx 64\text{MB}$).
   *   Index directly via `index = hash & (2^k - 1)`.
   *   *Eviction Strategy (Two-Tier or Aging)*: If bucket collision occurs:
       $$\text{Overwrite if: } \text{entry}_{\text{new}}.\text{depth} \ge \text{entry}_{\text{old}}.\text{depth} \quad \text{OR} \quad \text{entry}_{\text{old}}.\text{age} < \text{current\_generation}$$

3. **Eliminating Allocation from the Call Stack**:
   *   Eliminate heap allocations from the recursion path. Use stack-allocated move buffers rather than returning dynamic arrays/vectors of child states.
   *   Represent states using compact structures (e.g., 64-bit Bitboards for Connect-Four/Chess), making moves fast to compute, copy, and undo on a shared state.

### Scenario 3: Designing Admissible Heuristics for Complex Planning
**Interviewer Prompt**: *"You are writing a route-finding agent for an automated warehouse robot moving along a grid to retrieve pallets. The robot can move horizontally, vertically, carry varying loads (which lower speed), and has limited battery consumption per step. Standard Manhattan distance results in non-optimal paths and high collision rates. How do you design an optimal, admissible heuristic?"*

#### Probing Patterns
*   Did the candidate check for consistency, or just admissibility?
*   Do they understand how state abstraction and Pattern Databases create tighter heuristics?

#### Staff-Level Response Architecture

1. **Deconstruct the State Space Tuple**:
   *   A node is not just $(x, y)$. The state is $S = (x, y, \theta, m, B)$ where $\theta \in \{0, 90, 180, 270\}$ (orientation), $m$ is current payload mass, and $B$ is battery level.
   *   The edge cost function is dynamic:
       $$c(s, a, s') = \Delta t(a, m) + \text{Penalty}(B)$$

2. **The "Relaxed Problem" Formalism**:
   *   To guarantee admissibility ($h(s) \le h^*(s)$), mathematically relax one or more problem constraints:
       1. *Relaxation 1*: Ignore turns ($\theta$) and payload acceleration limits. Cost defaults to Manhattan distance divided by the theoretical maximum velocity:
          $$h_1(s) = \frac{|x_s - x_g| + |y_s - y_g|}{v_{\max}}$$
       2. *Relaxation 2*: Ignore the grid obstacles, but incorporate the kinematic rotational time (minimum turn degrees needed to face the goal divided by max angular velocity $\omega_{\max}$):
          $$h_2(s) = h_1(s) + \frac{|\Delta \theta_{\min}|}{\omega_{\max}}$$
   *   Because both represent valid relaxations, their maximum remains admissible and strictly dominates either one alone:
       $$h_{\text{combined}}(s) = \max(h_1(s), h_2(s))$$

3. **Pattern Databases (PDB)**:
   *   If obstacles are static, precompute an exact reverse Breadth-First Search from the drop-off zone ignoring dynamic obstacle collisions, saving the true travel cost in an uncompressed 2D/3D table.
   *   This turns complex pathfinding into an $O(1)$ memory lookup that serves as a consistent heuristic. This guarantees minimal node exploration for the online A\* instance without sacrificing path optimality.
